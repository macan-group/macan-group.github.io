# Email authentication for macanco.com (SPF, DKIM, DMARC)

The site's forms send mail through `sendmail.php` → the cPanel server's local
MTA (Exim), **From `website@macanco.com`**, delivered to `contact@macanco.com`.
For that mail (and any mail you send from the `contact@` mailbox) to reach
inboxes instead of spam, the `macanco.com` DNS zone needs three records.

> **Fastest path:** cPanel → **Email Deliverability** → row for `macanco.com` →
> **Manage** → **Repair**. cPanel generates SPF + DKIM automatically and, if it
> controls your DNS, installs them. If your DNS is elsewhere (registrar,
> Cloudflare, Hostinger hPanel), it shows the exact records to copy — use the
> values below as a cross-check.

All three are **TXT** records. Set TTL to `3600` (1 hour) unless noted.

---

## 1. SPF — which servers may send as `macanco.com`

| Field | Value |
|---|---|
| Type | `TXT` |
| Name / Host | `@`  (i.e. `macanco.com`) |
| Value | `v=spf1 +mx +a ip4:SERVER_IP ~all` |

- Replace `SERVER_IP` with the cPanel server's IPv4 (cPanel home → **Shared IP
  Address**, or `dig +short macanco.com` after DNS points at it). Add
  `ip6:SERVER_IPV6` too if the server has one.
- If the host publishes its own include (common on Hostinger:
  `include:_spf.mail.hostinger.com`), use their documented string instead, e.g.
  `v=spf1 include:_spf.mail.hostinger.com ~all`.
- **Exactly one** SPF record per domain. Merge, never add a second.
- `~all` (softfail) while testing; move to `-all` (hardfail) once you've
  confirmed nothing legitimate is sent from elsewhere (e.g. a CRM, Mailchimp —
  each needs its own `include:`).

Check: `dig +short TXT macanco.com` → should show one `v=spf1 …` line.

---

## 2. DKIM — cryptographic signature on every outgoing message

DKIM keys are generated by the sending server. **Do not invent this value** —
take the public key cPanel produces.

1. cPanel → **Email Deliverability** → **Manage** for `macanco.com`.
2. Copy the **DKIM** record it shows. It looks like:

| Field | Value |
|---|---|
| Type | `TXT` |
| Name / Host | `default._domainkey`  (→ `default._domainkey.macanco.com`) |
| Value | `v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIB…` (long, one string) |

- The selector is usually `default` on cPanel. Some hosts use `cp` or a dated
  selector — use whatever the panel shows.
- Many DNS UIs split long TXT values; paste it as a single quoted string, or in
  `"chunk1" "chunk2"` form if the UI requires ≤255-char segments.
- Key should be **2048-bit**. If cPanel offers only 1024, regenerate at 2048 in
  Email Deliverability.

Check: `dig +short TXT default._domainkey.macanco.com` → one `v=DKIM1; …` line.
Then send a test to <https://www.mail-tester.com> and confirm `DKIM: pass`.

## 3. DMARC — policy + reporting

| Field | Value |
|---|---|
| Type | `TXT` |
| Name / Host | `_dmarc`  (→ `_dmarc.macanco.com`) |
| Value (start here) | `v=DMARC1; p=none; rua=mailto:dmarc@macanco.com; ruf=mailto:dmarc@macanco.com; fo=1; adkim=s; aspf=s; pct=100` |

Tag meaning:

| Tag | Meaning |
|---|---|
| `p=none` | Monitor only — don't act on failures yet. Collect reports for ~2 weeks. |
| `rua=` | Where aggregate (daily XML) reports go. Create the `dmarc@macanco.com` mailbox or alias first. |
| `ruf=` | Where forensic/failure reports go (optional; some providers ignore it). |
| `fo=1` | Send a failure report if **either** SPF or DKIM fails alignment. |
| `adkim=s` / `aspf=s` | Strict alignment — the visible `From:` domain must match exactly. Use `r` (relaxed) if you later send via a subdomain. |
| `pct=100` | Apply the policy to 100% of mail. |

**Rollout:**

1. `p=none` → watch the `rua` reports until only your server / known senders
   appear and all show `dkim=pass` + `spf=pass`.
2. `p=quarantine; pct=25` → then `pct=100`.
3. `p=reject` — final state; spoofed mail is refused outright.

Check: `dig +short TXT _dmarc.macanco.com`.

## 4. Supporting records

- **MX** — must point at the mail host (cPanel: usually `mail.macanco.com`
  priority `0`, with an `A` record `mail.macanco.com → SERVER_IP`). Email
  Deliverability flags this if missing.
- **PTR / reverse DNS** — `SERVER_IP` should resolve back to the server's
  hostname. You usually can't set this yourself on shared hosting; open a ticket
  with the host if mail-tester shows a PTR warning. On a VPS, set it in the
  provider panel.
- **`website@macanco.com`** — the envelope `From` in `sendmail.php`. Create it
  as a real mailbox or an alias to `contact@`, otherwise bounces vanish.

---

## 5. Verify end to end

```sh
dig +short TXT macanco.com                       # SPF
dig +short TXT default._domainkey.macanco.com    # DKIM
dig +short TXT _dmarc.macanco.com                # DMARC
dig +short MX  macanco.com                        # MX
```

Then:

1. Submit a form on the live site.
2. Confirm the mail arrives at `contact@macanco.com` (check Spam too).
3. Forward it to `check-auth@verifier.port25.com` or send a fresh test to
   <https://www.mail-tester.com> — aim for 10/10 with `SPF pass`, `DKIM pass`,
   `DMARC pass`.
4. Reply to a form submission — the `Reply-To` is the visitor's address, so it
   should go straight to them.
